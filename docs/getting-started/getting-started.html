Upstream Torizon OS on Verdin iMX8M Plus

Torizon OS on mainline Linux 7.3.1, with upstream Mesa and GStreamer and our changes, tuned for the i.MX 8M Plus. No NXP downstream drivers: GPU, NPU, video encode and decode, ISI and display all run on upstream code. This guide installs it and shows each unit working in a few commands.

Why this release

What It Adds to Upstream

Mainline Linux and Mesa already run the i.MX 8M Plus well for CPU, memory, display and video decode. What they lack is GPU compute, a usable NPU, a video encoder and 2D conversion. This release closes those gaps. The table compares mainline today (Linux 7.3, Mesa main, the base of Mesa 26.3), this release and NXP's downstream stack in Torizon OS 7.7.0, all measured on the same Verdin iMX8M Plus Quad.

Where Upstream Was Already Ahead

  • Hardware video decode: H.264 1080p 202 fps against 172, HEVC 378 against 291 (+17% and +30%).
  • Playback on HDMI uses 1–3% of the CPU against 6–8%: decoded frames go to the GPU without a copy.
  • The NPU is ready in 0.5–1 s on the first inference, against 3.3–9 s for NXP's VX delegate.
  • CPU, memory and Ethernet are identical; the kernel is current, with years of upstream fixes.

Install

Install the Release

What You Need

  • A Verdin iMX8M Plus Quad module. QuadLite modules have no NPU and no VPU. Tested on Verdin iMX8M Plus Quad 4GB WB IT.
  • A Dahlia or Verdin Development Board carrier board, on Ethernet with DHCP.
  • A USB stick of 1 GB or more for the installer image.
  • An HDMI monitor for the display demos. Everything else also works without a display.

1Get the Release

Download from the GitHub release engineering-release-1 of meta-tz-mainline:

The containers are on Docker Hub: samnite/tz-upstream-imx8mp:3 is the graphics, compute, NPU and video stack, a base for your applications; samnite/tz-upstream-imx8mp-demo:1 adds the demos and the self-test of this guide.

2Install It with Toradex Easy Installer

  1. Unpack the archive on the USB stick (FAT32 or ext4). It makes one folder with image.json in it: 
    tar xf torizon-docker-verdin-imx8mp-Tezi_8.0.0-devel-20261123173501+build.0.tar -C /media/<stick>
  2. Start Toradex Easy Installer on the module. If the module does not start it already, load it over USB in recovery mode, as described in Toradex's guide Loading Toradex Easy Installer.
  3. Plug in the USB stick. The installer lists Torizon OS (UPSTREAM) 8.0.0-devel-20261123173501. Select it, press Install and confirm. Installing takes a few minutes.
  4. Reboot when the installer says it is done.

3Log In

The board gets its address over DHCP and announces itself over mDNS as verdin-imx8mp-<serial>.local, where <serial> is the 8-digit serial number on the module label. The user is torizon with password torizon; change it with passwd.

ssh torizon@verdin-imx8mp-<serial>.local
$ uname -r
7.3.1-8.0.0-devel-00018-g1dd50f6c1323
$ grep PRETTY_NAME /etc/os-release
PRETTY_NAME="Torizon OS Upstream 8.0.0-devel-20261123173501+build.0 (wrynose)"

Everything at Once: tz-demo all

Runs all units together for 60 seconds (tz-demo all 300 for five minutes), then checks the kernel log for GPU hangs and video errors:

  • a camera-like 1080p30 chain: a live YUY2 source goes through the ISI to NV12, the VC8000E encodes it to H.264, the G1 decodes it and the GPU shows it on the display;
  • HEVC 1080p decoding on the G2, clip after clip, as fast as it goes;
  • image classification on the NPU, every result checked against the CPU;
  • OpenCL memory kernels on the GPU (clpeak).

Develop

5Use the Stack in Your Own Container

Start from the base container. Its environment already selects the upstream Mesa and GStreamer, turns on compute and sets the NPU options. Run it with --privileged -v /dev:/dev -v /run/udev:/run/udev:ro, as above. It has no Python and no TensorFlow Lite runtime; the demo Dockerfile in containers/tz-upstream-imx8mp-demo shows how to add them.

FROM samnite/tz-upstream-imx8mp:3

Play a video on HDMI. Decoders write padded frames. Sinks that take them as they are (glimagesink, waylandsink, kmssink, fakevideosink) are fast; a plain fakesink or an appsink without video meta makes the decoder copy each frame with the CPU, at 20 to 50 fps for 1080p.

gst-launch-1.0 filesrc location=video.mp4 ! qtdemux ! h264parse ! v4l2slh264dec ! glimagesink

Encode 1080p H.264 from a YUY2 source through the ISI. With capture-io-mode=dmabuf-import the ISI writes straight into the encoder's buffers; without it every frame is copied and a live 1080p30 source cannot keep up.

gst-launch-1.0 <source> ! video/x-raw,format=YUY2,width=1920,height=1080 ! \
    v4l2convert capture-io-mode=dmabuf-import ! video/x-raw,format=NV12 ! \
    v4l2slh264enc rate-control=cbr bitrate=8000000 ! h264parse ! matroskamux ! filesink location=out.mkv

Run a TensorFlow Lite model on the NPU, in Python with ai-edge-litert. The NPU runs quantized (int8 and uint8) models; operations it does not support stay on the CPU. The first inference compiles the model for the NPU and takes up to a second.

from ai_edge_litert.interpreter import Interpreter, load_delegate

npu = load_delegate("/opt/mesa/lib/libteflon.so")
interpreter = Interpreter("model.tflite", experimental_delegates=[npu])

OpenCL. clinfo lists the device "Vivante GC7000 rev 6204" on the rusticl platform. OpenCL applications and OpenCV's OpenCL path work without changes.

Limits

Known Limits

  • The GPU runs one job at a time and cannot preempt it. Long OpenCL kernels hold it and the display waits: with clpeak's compute test running, a 30 fps video on HDMI drops to about 5 fps.
  • The kernel stops any single GPU draw longer than 500 ms. Qt Quick 3D's runtime light-probe filtering and some Godot scenes hit it; bake light probes offline. OpenCL is not affected: Mesa splits long launches.
  • glmark2 needs --visual-config alpha=0 on this display (tz-demo gpu sets it): the display controller does not scan out frame buffers with alpha.
  • No Vulkan. No HEVC encoding: the hardware has it, but there is no kernel interface for it yet.
  • OpenCL reports the embedded profile; NXP reports the full profile.
  • The container is Debian sid, not the trixie base of Torizon's own containers.
  • systemd-networkd-wait-online reports a failure at boot; the network works.
